# ADR-2026-11-10-05: 代谢与节律 v1（精力重标定 + 疲惫门禁）

- 状态：已接受
- 日期：2026-11-10
- 关联任务：ONES TASK-018

## Context

生命体审计发现：当前只有状态、没有行动选择；drives 和心跳能算出「想
说话」，但不会算出「该休息」。实机数据：精力长期 1.3/100，心跳
`last_speak_time=0`，主动发言从未真正发生；普通聊天里她只能说「没有心跳」。
根因不是心跳坏了，而是：

1. 每条 AI 回复扣 2 精力，活跃期 5 分钟内完全不恢复；连续聊天必然见底。
2. 见底后只有「energy_brake」把 urgency 压低，没有任何「疲惫」的明确
   原因或行为倾向；她不知道自己为什么不想开口。
3. 精力与真实 token 成本、休息/睡眠没有形成闭环。

代谢是未来所有自主行动的货币。先让「累」可解释、可恢复、会阻止主动
开口，再谈 LifeLoop 的行动选择。

## Options Considered

**A. 保持 2 精力/句、2/300s 恢复、4h 满血。** 现状；长聊必然见底，且
见底不可解释。否决。

**B. 重标定 + 疲惫门禁。**（已选）一句话 1 精力；安静 5 分钟后
3/300s 恢复；3h 满血；低于 15 时心跳明确 skip（not_tired），内感受
解释原因并建议休息。

**C. 立即做完整能量-预算经济（精力↔token↔休息行动）。** 方向正确，但
属于 LifeLoop；本任务先把货币和门槛定对，避免行动循环建在坏掉的稳态上。

## Decision

采用 B。

- `DEFAULT_HEARTBEAT`：
  - `msg_energy_cost`: 2 → 1
  - `energy_recovery_per_300s`: 2.0 → 3.0
  - `energy_full_secs`: 14400 → 10800（3h）
  - 新增 `tired_threshold`: 15（钳位 0-100）
- `heartbeat.decide` 新增门禁 `not_tired`（在睡眠窗之后、urgency 之前）：
  `energy < tired_threshold` → skip，reason `not_tired`。
- `heartbeat_journal.REASON_CN` / `interoception.GATE_CN` 增加 `not_tired`
  （「太累了」/「精力」）。
- `interoception.body_text` 增加代谢说明（每句话消耗/安静恢复/疲惫阈值）
  与「你现在很累，最想安静歇一会儿」的建议；`gates_text` 增加精力/阈值行。
- 保留「活跃期 5 分钟内不恢复」的原则：陪伴不是休息；只是把消耗减半、
  脱离活跃期后的恢复加快。

## Impact

- 连续聊天掉电速度减半；停止互动 5 分钟后回血更快，3 小时满。
- 精力 <15 时不再尝试主动开口；心跳日志会显示「太累了」，内感受能
  解释原因并建议休息。这会让「累」成为可观察、可叙事的生命状态。
- 冒烟：更新 drives 恢复值、主动发言扣费 2→1 的断言；新增疲惫门禁用例。
- 不变：不新增行动选择、不改权限/预算、不改被动/主动对话链路。

## Risks

- **仍可能见底**：超长对话仍可把精力压到 0；只是变慢。真正的「去休息」
  需要 LifeLoop 的 rest 意图，下个任务再做。
- **疲惫会让它更安静**：这是有意行为变化；用户可能觉得「怎么不主动了」，
  内感受/日志会解释。
- **精力与真实成本仍分离**：1 精力 ≠ 1 分钱；精力是生命节奏，token 是
  账本。合并留给「生存经济」任务，避免现在把两种语义混在一起。
- **参数是默认值**：用户 config 里显式写过的值不会被覆盖；手改过的老
  配置可能仍是 2/2/4h，行为与默认不同。

## Deferred

- rest 意图/自主睡眠（LifeLoop v1）。
- 昼夜节律对恢复速率的调制（睡眠窗内更快）。
- 精力 ↔ 日 token 预算的生存经济。
- 每日代谢/活动摘要（今天说了多少、休息了多久、学会了什么）。
