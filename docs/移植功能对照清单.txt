三、不可对等项（阻塞原因 / 替代方案 / 影响 / 风险）
======================================================================
N1 Electron 下载与解压（helper/electron.ts：43.3.0、npmmirror、10 分钟超时、
   进度 3000ms、下载日志借用工作气泡 api 槽 12s 清槽）
   阻塞：Python 版无 Electron 运行时。
   替代：以「运行时自检」（Python/Qt 版本、素材完整性、字体）为等价槽位，
   复用 api 工作槽显示进度。
   影响：无 Electron 下载体验。风险：低。
N2 桌面 Helper 子进程（spawn/IPC 11 频道/bridge 行协议/宿主探活/重启退避/熔断）
   阻塞：PySide6 单进程无渲染子进程。
   替代：单进程内直接调用等价函数；崩溃恢复改为「单实例守护 + 异常重启」。
   影响：无跨进程隔离。风险：中（崩溃会带走主进程）。
N3 浏览器内浮层（DSH Web overlay，display=web/both）
   阻塞：无 DSH 网页宿主。
   替代：display 保留四值语义，web 仅对本地 HTTP 服务可见（不渲染窗口）。
   影响：无网页内桌宠。风险：低。
N4 DSH 会话事件源（turn/start、tool/call、approval/asked、agent/error）
   阻塞：剥离后无宿主事件。
   替代：本地 API 主动推送（等价 POST /work-status 与内部事件总线），
   并提供适配脚本入口对接 DSH 若仍在使用。
   影响：工作状态/气泡详情/通知/碎碎念的自动化触发依赖外部推送。
   风险：高（决定 C/D/S/G 是否有实际意义）→ 见待确认项 Q1。
N5 Cordis 服务面（petApi7340.getState/menuEvents/pose/progress）
   阻塞：无 Cordis 插件系统。
   替代：Python 侧同名服务对象（进程内单例），并可选经本地 HTTP 暴露。
   影响：无第三方插件调用面（除非走 HTTP）。风险：中。
N6 Windows 安装器/签名/NSIS（electron-builder 配置在快照中不存在）
   阻塞：无配置可依，且需安装器工具链。
   替代：PyInstaller onefile + 可选 Inno Setup/NSIS 脚本。
   影响：无签名与自动更新。风险：中 → 见待确认项 Q5。

[动作调度日志与间隔闸门（2026-10-31）]
  日志：logs.txt 中以 "ACTION t=..s ..." 记录 start / block / queue / end / walk / work；
        start 带 name/prio/dur/prev，队列带 set/drop/expire/start，结束带 gap；
        动作提前结束会记 "end early name=.. remain=.."。
  根因：
    1) 动作库皮肤原先把调用方 1.6~2.8s 的拍子放宽到 8s，而素材是 10s，
       所以每段尾部被截掉 2s；
    2) 动作未播完时新请求（高优先级/点击/事件/工作）直接抢占，造成当前动作截断；
    3) dsh 的 idle 分支走 action_binding 成功时没设 _idle_cd，下一帧继续抽；
    4) _end_emote 结束就立刻播缓存/立刻接回工作动画，段与段 0 间隔；
    5) 工作动画用手动级，绕过所有闸门。
  修复：
    - single_shot 皮肤一律按素材 anim_duration 播完整段，不再用调用方时长截断；
    - 普通演出动作在播时，任何新请求（含点击/手动/事件）都只排队，不截断当前动作；
      仅拖拽可接管；工作长驻动画可被点击/手动切换；
    - 动作结束进入 3–5s 全局静默：走位不准起步，队列不准释放；
      缓存动作由 _tick_action_queue 到点再播，TTL 60s，过期丢弃（日志 expire）；
    - 队列规则：低优先级只留最高一条，同优先级保留先到；
      静默/播放期间来的更高优先级会顶掉队列里的低优先级，但不抢占当前动作；
    - 每次 idle 抽签后必设冷却 72–120s（dsh）、12–24s（whale）；
    - 工作动画降为空闲级并排队，状态清除/新状态时同步清队列。
  证据（当前代码仿真）：螃蟹走路 dur=10.0 实播 10.02s → end gap=4s →
        queue start 3.56s；动作结束后走位等 4.12s 才起步；
        旧运行日志中出现的 0s 间隔（end 与 walk start 同刻、walk stop 与 queue start 同刻）
